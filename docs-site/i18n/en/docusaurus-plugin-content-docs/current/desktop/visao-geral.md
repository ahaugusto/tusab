# Desktop app (discontinued)

:::warning Desktop app discontinued
The desktop app was discontinued on 2026-11-19 and no longer receives fixes or updates. The code mentioned on this page is in the [`desktop-final`](https://github.com/criaugu/tusab/tree/desktop-final) tag, no longer on `main`. This page is kept only as a record.
:::

Before the AI extension, Tusab was distributed as a desktop application: an Electron window with a Python backend (FastAPI) and **its own chat** (the Assistant), which answers with local RAG using Ollama or an external provider. The last version was 1.0.64, for Windows and macOS. The 1.0.x releases remain published on GitHub as history, and the code is in the `desktop-final` tag.

## Differences from the extension

| | Extension (`tusab-mcp/`) | Desktop app |
|---|---|---|
| Who converses | The user's AI, through the [MCP tools](/ferramentas-mcp) | The app's [Assistant](/funcionalidades/assistente-rag) |
| Study material | Generated by the AI, stored by Tusab | Generated by the app itself ([Study Mode](/funcionalidades/modo-estudo)) |
| Index | SQLite FTS5 (`data/tusab.sqlite`) | In-memory BM25 + FTS5 + optional vector search; stored in LanceDB (`data/agent_index/`) |
| Images and audio | Stored as originals, not read | Image description (multimodal Ollama or RapidOCR) and audio transcription (faster-whisper) |
| MCP integration | It is the MCP server itself (15 tools) | [Desktop MCP server](/funcionalidades/mcp-server) with 2 tools |
| Google Drive, optional telemetry | No | Yes |
| Installation | `.mcpb` package or MCP configuration | [Installers](/desktop/instalacao) `.exe` and `.dmg` |

Both write **the same folder structure** (`data/neural/{projeto}/…`): the extension opens the app's data folder, and `.tusab` works both ways. The extension screen is the same React interface as the app, built in extension mode.

## Stack

**Backend:** Python 3.12 (embedded in the installer) + FastAPI + Uvicorn, REST API on `localhost:8001`. CI runs the tests with Python 3.11.
**RAG:** `rank_bm25` (BM25Okapi) + SQLite FTS5 + optional vector search via Ollama (`nomic-embed-text`); CrossEncoder and KeyBERT (`sentence-transformers`) supported in the code, left out of the standard installer.
**Index storage:** LanceDB (`data/agent_index/{projeto}.lancedb/`).
**Interface:** React 19 + Vite + Tailwind CSS 3 + Framer Motion + Lucide React + react-i18next (pt, en, es), in `web_interface/`, built with `npx vite build` into `web_interface/dist/`.
**Desktop:** Electron 44 + electron-builder (NSIS on Windows; signed and notarized `.dmg`/`.zip` for macOS arm64) + electron-updater (updates via GitHub Releases).
**Extraction:** yt-dlp (bundled) + pdfplumber + python-docx; web pages with trafilatura.
**Images:** multimodal Ollama (llava/gemma3), with RapidOCR as an alternative.
**Audio:** faster-whisper (`base` model, CPU).
**Drive:** Google OAuth2, `drive.file` scope.

## Backend layers

```
api_tusab.py           entry point; mounts the FastAPI app, routers and startup migrations
  │
  ├── tusab_engine/api/          FastAPI routers by domain
  │     router_status.py           /status, /drive-auth, /history, /open-folder, /agent/mcp/config
  │     router_extraction.py       /set-channel, /start, /pause, /cancel, /queue/*
  │     router_agent.py            /agent/* (chat, configuration, index, Ollama, streaming)
  │     router_estudo.py           Study Mode
  │     router_repositorio.py      /repositorio, /relatorio, /neural/*, /reset-total
  │     router_exports.py          /export/* (zip, markdown, docx, xlsx, pdf)
  │     router_fontes.py           public sources
  │     router_digest.py, router_metrics.py
  │
  ├── tusab_engine/motor/        extraction (extraction.py), Drive, public sources, FHIR, arXiv,
  │                              web page, automatic updates
  ├── tusab_engine/agent/        local RAG: index.py, chat.py, fts.py, embeddings.py,
  │                              calibration.py, lance_store.py, llm_providers.py, tts.py…
  ├── tusab_engine/mcp_server.py desktop MCP server (2 tools)
  ├── tusab_engine/state.py      shared state (AppState) + LogRedirector
  └── tusab_engine/storage.py    data paths + atomic writes
```

**Dependency rule (acyclic):** `api → agent | motor → storage`; never the reverse. `motor_tusab.py` and `agent_tusab.py`, at the root, are re-exports for compatibility with Electron and older code.

## Desktop app data

| Context | Data root |
|---|---|
| Installed app | Electron's `userData` folder: `%APPDATA%\Tusab` (Windows), `~/Library/Application Support/Tusab` (macOS) |
| Development | Repository folder (`./data/`) |
| Overridden | `TUSAB_DATA_DIR` variable |

Besides the common structure described in [Data and storage](/arquitetura/dados-e-armazenamento), the desktop app uses:

| Path | Content |
|---|---|
| `data/agent_index/{projeto}.lancedb/` | Assistant index (LanceDB) |
| `data/config/agent_config.json` | Assistant configuration; stores the `__encrypted__` marker instead of the API key |
| `config/keystore.json` (in the `userData` folder) | API keys encrypted with `safeStorage` (DPAPI on Windows, Keychain on macOS) |
| `data/config/token.json`, `credentials.json` | Google Drive OAuth |

`config/` **should not be shared** or go to a cloud backup without encryption: it may contain OAuth tokens and the Assistant configuration. The app creates a `LEIA-ME-SEGURANCA.txt` in the data folder explaining this.

At startup, idempotent functions migrate old layouts if they exist: `migrar_cerebro_para_neural()`, `migrar_gestao_para_cerebro()`, `migrar_pastas_para_ingles()`. In the switch to LanceDB (v1.0.55), only storage changed (incremental indexing about 12 times faster); ranking is still in-memory BM25, because LanceDB's native search lost precision in tests.
