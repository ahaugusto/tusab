# Languages

Tusab works in **Portuguese, English and Spanish** (`pt`, `en`, `es`).

## What changes language

| Part | How |
|---|---|
| Tusab screen | The interface translation files (`web_interface/src/locales/pt.json`, `en.json`, `es.json`) |
| Plugin messages (tool responses, errors, notices) | The `t()` function in `tusab-mcp/src/nucleo/idioma.js`. The key is the Portuguese sentence itself; translations live in `src/nucleo/textos/en.js` and `es.js` |
| Tool titles in the conversation | Updated immediately when the language changes |
| Claude's "+" shortcuts (prompts) and the search and citation rules | The 21 prompts and the rules exist in all three languages; titles and texts are updated immediately |
| Claude Desktop extensions screen | `manifest.json` in pt-BR (`default_locale`) and `mcpb-resources/en-US.json` and `es-ES.json`, generated by `node scripts/gerar-recursos-manifesto.mjs` |

The tools' technical descriptions (read only by the AI) stay in Portuguese. The server instructions ask the AI to always answer in the language the user writes in.

## Where the language comes from

1. The screen sends the chosen language in the `X-Tusab-Idioma` header of every API call (read only after the [session key](/tela#local-server-security) is checked).
2. The plugin saves the choice in `data/config/idioma.json`, so it also applies to what the AI sees.
3. Before the screen is opened for the first time, the `TUSAB_IDIOMA` variable (if set) or the system language applies; if it isn't pt, en or es, the plugin uses English.

## What stays in Portuguese on purpose

To stay compatible with the desktop app, these are **not** translated:

- formats written to disk: labels of the `.txt` blocks, management CSV statuses (`Sucesso`, `Sem Legenda`…), the `[Página N]` marker in PDF texts;
- search terms sent to public sources;
- texts used to detect formats (WhatsApp, meetings, legal documents);
- tool names (`tusab_buscar`…).

## Test

`tusab-mcp/test/idioma.test.js` fails if any sentence used in the code lacks a translation in `en.js` or `es.js`, or if the variables (`{nome}`) don't match. Tests always run in Portuguese, whatever the system language (`test/_ambiente.js` sets `TUSAB_IDIOMA=pt`).
